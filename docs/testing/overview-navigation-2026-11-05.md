## 问题与改动

| 真实复现的问题 | 实现 |
| --- | --- |
| 搜索“项目”有匹配，但 ArrowDown／Enter 仍停在概览；点击结果后浮层可能遗留。 | 输入使用 combobox，结果使用 listbox／option；上下键循环选择，Enter 激活，Escape／Tab／外部点击／选择／路由统一收起。键盘选择时焦点留在输入，活动项和可访问属性同步。IME 不误触发，无结果时 Enter 不跳转。 |
| 手机搜索字号过小；结果可能出界或被首页标题与按钮盖住。 | 手机输入 16px、44px 高；结果按视口两侧 16px 安全距离定位，缩放不累计偏移；顶栏建立明确层级。最终浮层使用 99% 白色及 16px 局部模糊，底层文字不干扰结果阅读，键盘焦点环跟随整个圆角搜索框。 |
| 手机首屏被四张统计卡和“暂无封面”占位占据，实际项目与入口在下方。 | 仅压缩概览手机统计卡，收起手机无封面占位；真实项目名称、状态和进入制作优先呈现，保留只读阅读入口。桌面保留完整布局。统计副标签为“待处理／已归档”，当前项目身份只在继续创作卡片中显示。 |
| “阅读故事”误把没有模型梗概的手写稿提示为尚未生成剧本。 | 概览预览直接读取已保存正文并标明版本，只读显示且转义文本；旧稿缺正文时诚实展示已有梗概或补充提示。`script_ready` 显示为“剧本已保存”。 |

没有增加装饰图片、字体服务、前端依赖或后端接口。

## 浏览器实测

使用专用前台 Chrome 测试会话，仅只读访问原有验收项目 `proj_1c4e7aafd77e`。新建项目入口只打开后取消，没有创建测试数据或提交任务。

- Ctrl+K 搜索“项目”，ArrowDown／Enter 正确到项目库；选择后结果隐藏，`aria-expanded=false`，清除活动项。
- 搜索“复核”匹配三个项目，ArrowUp／Down 首尾循环，当前项有明确选中态；点击搜索项目可进入对应真实剧本页。
- Escape 保持搜索输入焦点并收起结果；Tab 正常移到下一个控件；零结果 Enter 不跳转；输入法组合期间不激活结果，结束后恢复结果。
- 点击外部和路由切换均收起结果。
- 手机导航展开后 Escape 返回菜单按钮；Enter 选择项目库后导航收起。桌面主导航及概览主要入口均实际操作。
- 手机“阅读故事”可读取已保存 V2 的完整 1011 字符正文，不再显示“尚未生成剧本”；关闭后回到触发入口。“进入制作”读取同项目 V2，不写数据。
- 新建项目对话框取消后回到新建按钮，没有提交。

最终样式在 320×700、390×844、768×1024、1440×1080 复核：页面滚动宽度等于视口宽度；所有可见搜索结果的命中点都属于对应结果，未被底层控件覆盖。390px 浮层左右边界为 16／374，320px 为 16／304。手机输入字号为 16px、高度 44px。

390×844 下项目标题顶部约 562px，“进入制作”按钮底部约 718px，均在首屏内。桌面与手机最终截图中统计副标签均核对为“待处理／已归档”。最终弹层计算背景为 `rgba(255,255,255,0.99)`、模糊 16px；查看截图确认底层标题不与建议行混读。

最终页面未记录未捕获错误。手机验证为浏览器视口模拟，没有据此声称完成 iOS 实机软键盘验证。最终截图启用减少动画偏好，便于稳定核对布局。
